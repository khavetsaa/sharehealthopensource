# Contributing to SHARE

Clinicians, engineers and data scientists are welcome.

1. Open an issue describing the change or the clinical question.
2. Fork, create a branch, and add tests for any logic change (`pytest -q` must pass).
3. Never commit real patient data. Use `share/simulate.py` for synthetic data.
4. Changes to thresholds, risk weights or compression limits need review by a clinician on the team.
5. Be respectful. Disagreements are about the work, never the person.

By contributing, you agree that your code is released under the Apache 2.0 licence.
